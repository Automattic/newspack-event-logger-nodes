What fires and what listens along one logged request

Priorities decide the order the record reads in: the profiler writes ahead of the instrumentation, a hook's span opens before its callbacks and closes after them, and the terminal is written from a shutdown function so a fatal still ends the record.

before the bootstrapplugins_loaded @-10001

The rows reach the firehose, and the logger is built

Log_Manager::instance() is constructed here when nothing else has: it resolves the rule matching REQUEST_URI, adopts and unsets the profiler's request_time and request_ts, and, when the rule says log, registers finish() as a shutdown function and writes process (start) stamped with the moment PHP began the request and the governing rule id. The plugin rows follow as <slug> plugin (start) / (complete) pairs carrying their own ts. One below the default hook_start_priority, so they precede what App\Core records for the same hook. A skip rule, no rule, enable_logging off or a root process leaves the instance inert and every write returns false.

new App\Core() binds the governing rule's instrumentation

Each of the rule's hooks gets three registrations. A significant_events name the list omits is bound too, once a trailing  hook is stripped. Never bound: a custom_events category (the application logs it itself), plugin_loaded (the drop-in owns it), query under log_queries (the SQL span covers it), and any name Hook_Categorizer::is_internal() reports, a newspack_nodes or newspack_event_logger_nodes prefix, because instrumenting one re-enters the logger's own bootstrap.

Two more pairs, each closed ahead of the other listeners so the span covers the work and not its audience. The HTTP pair opens after every filter that could short-circuit the call; the query pair opens ahead of the filter chain:

log_http (absent means ON)pre_http_request @ PHP_INT_MAX (3 args) opens http, and only when $preempt is false: a short-circuit fires no http_api_debug, so a span opened for one would never close. http_api_debug @ PHP_INT_MIN (5 args) closes it with the status code.
log_queries (default off)defines SAVEQUERIES if it is not already. query @ hook_start_priority opens sql ahead of the filter chain, so a significant query hook's wrapped callbacks nest inside it; log_query_custom_data @ PHP_INT_MIN (5 args) closes it with the rewritten statement, literals replaced, and drains $wpdb->queries.

The same closure also registers the job-context filter and action, the newspack_nodes/settings_sync/value resolver, and the MCP route on rest_api_init; the three service CIs mount later, on newspack_nodes/request_graph_ready, when a command request builds its graph.

while the request runseach bound hook

Spans open and close; significant hooks are wrapped per callback

hook_start wraps a hook's own callbacks only where the rule names it in significant_events, and only those registered strictly between hook_start_priority and the spacer: everything at or above the spacer is the logger's own. A callback whose reflection reports a by-reference parameter is skipped, because wrapping it breaks WordPress's by-reference contract. Each wrapper claims accepted_args = 99 and slices back to the original's count before calling it. Under trace_hooks the start entry's l names the calling frame; under trace_callers its caller carries a deep backtrace, at most that many per hook.

A job gets its own request context

Log_Manager::begin_job_context_filter() opens it unless an earlier listener declined, passing the decision through: $_SERVER is snapshotted, the live instance suspended, and the request rewritten to a synthetic /jobs/{handler}/{id}. end_job_context() restores it; the $_SERVER stack IS the pairing record, and func_num_args() >= 3 with a null outcome marks the context aborted. Both ends fire newspack_event_logger_nodes_scope_changed, and App\Core rebinds its instrumentation to the restored scope's rule.

finish() writes the terminal, after a fatal too

Idempotent. Every frame still on the timer stack drains as (orphaned), innermost first; then process (complete) carries status_code, or the fatal's message, file, line, type and offending plugin with error_status: F when error_get_last() reports one of FATAL_TYPES. A cooperative stop landing mid-finish writes process (aborted) with error_status: A instead, then re-raises. Without a terminal the record strands in flight until the builder evicts it.
