Outbound HTTP is timed as a span, and a short-circuited request opens nothing

WP_Http::request() is not a hook, but WordPress brackets it: pre_http_request before, http_api_debug after. The pair is NOT balanced, and where each callback sits in its chain is the design. Bound for any log rule whose log_http is not an explicit false.

PHP_INT_MIN · http_endfirst to hear: pops the label it OPENED, writes http (complete) with the status code
every later prioritythe other listeners, outside the span

It pops rather than re-deriving the label from the URL: a redirect hands the action the FINAL url, and a label that no longer matched would leave the span open. Every return path but the short-circuit fires the action, so within one request the pair is exact.

The short-circuit fires no close

WP_Http::request() answers a non-false $preempt with a bare return $pre; and never fires http_api_debug. A span opened for it would never close and would adopt every row after it: the severed-span damage decision 13 bounds. A short-circuit is a cache hit with no I/O to time.

Named for its caller, not its host

l is origin_frame( true ), which climbs past the class that applied the filter at TRANSPORT_ORIGIN_DEPTH (16) rather than ORIGIN_DEPTH (8): "which of my code paths makes this call, how many times" is the reader's question. It climbs whatever decision 23's trace_callers says, because that budget attaches caller to hook entries alone.

The record that shows the cost

A BDN wp-admin/post.php request: 41.7 s wall against 12.2 s CPU, with Image_CDN::filter_the_content @999999 holding 29.4 s of self time and no interior. The 29.5 s off-CPU remainder has no name.

What it costs

Two registrations per request and two entries per remote call; zero on a request that makes none. Absent log_http means ON: only an explicit false drops the spans.

Never constructs the logger

Both callbacks ask Log_Manager::has_instance() first. A binding that outlived its request would otherwise build the logger inside the callback and stamp process (start) with that moment instead of the profiler's request_ts.
