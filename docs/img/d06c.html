The life of a stats row

Every stats Ledger is one SQLite file every flame-builder partition appends to. Rows sit in t order: each 30-second settle appends its span's deltas at the right edge, and the Router tick drops whole hour-long segments off the left edge once they pass the lifespan. A read names a window of t and aggregates what it finds.

What a row holds

Sums and counts, never means, so settles and partitions merge by addition and the dashboard divides at read time. A second row for one ( t, k, x ) is another settle's delta: a read sums them.

Nothing is capped but the servers: past 128 in a day, a server's rows file under Other, so the totals stay exact.

Nothing updates a row

A row goes only when its segment passes the lifespan, or a flush empties the Ledger. A Ledger keeps the retention window's hours, never fewer than 25.

wp nodes tables flush

Empties a Ledger by name in one transaction, without unlinking the file. wp nodes memcache flush leaves the statistics alone. They fill again as traffic arrives.
