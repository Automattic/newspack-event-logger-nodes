Each stream acquires its own lease before any header is sent, and the drain's finally releases it, so an idle close hands the slot back and each reopen acquires a fresh one. A poke refreshes only a lease its owner still holds: the pokes at 30 s and 45 s reach an open stream's lease, and a poke for a released lease is refused as SSE slot lease not owned.
The one lease stays held while data flows, and each poke resets its expiry to sse_slot_ttl from the poke. sse_slot_ttl, one value for every caller: 60 s default, floored at 45 s (3 × 15 s) by SSE_Slot_Pool::ttl(). A TTL must outlive the client's poke interval; at three intervals, one lost poke still leaves a refresh before expiry.

What ends a stream

Idle: no msg for sse_idle_timeout (15 s; 0 never closes). A clean close with no terminal frame. Heartbeats do not defer it, only data does, so a zero-message stream closing and reopening on this cycle is the normal case.

Lease lost: each drain tick CHECKS the lease and never refreshes it; a lost lease sends disconnect.

Nothing else in PHP: the stream runs set_time_limit( 0 ). PHP-FPM or a proxy still can.

Opening fails CLOSED

The slot is acquired before any header is sent, so a full pool, or a cache that will not take the lease, answers HTTP 429. The pool IS the rate limit and cannot fall through.

Only the client refreshes a TTL: a server that refreshed on check would keep a dead tab's slot alive as long as its drain loop ran.

Flush before the framework sleeps, never per event: per-event flushing tanks throughput on TLS and proxy paths.
