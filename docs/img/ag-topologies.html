Ten topologies: five primitives, and five compositions of them and the substrate's stock

A composition is mostly include lines: complete adds a Tee, and hub-control a Discovery_Collector and three add_setting lines. An included file runs once per load however many parents pull it in, which is why every composition mounts exactly one Topic_Probe. Frontmatter is read from the top-level file alone, so job-hub, job-spoke and hub-control restate the var they need; complete restates none. Every file ends with secure.

Substrate stock, included

topic-probe
topicprobe.p0

A 15 s Topic_Probe sweep writing per-worker Consumer stats. Every file reaches it.

job-intake
jobintake.pNjobs.pN

jobintake:consumer wired straight to jobs:partition under void_warranty. Standalone, it is a substrate-only install's job drain; the conflict gate refuses it beside either router.

job-worker
jobs.pNjobstats.p0

jobs:consumer in line mode, Job_Worker, a 15 s Job_Probe. var stale_timeout = 600, which an include skips.

settings-sync
settings.p0

settings:consumer and the Settings_Sync node on a 300 s tick, with the substrate's own add_setting lines: num_partitions, and each remote_* axis twice. var num_partitions = 1.

Plus Discovery_Collector 300 and three add_setting lines for rules, log_memory and flush_every_line, which must stay in step with Performance_CI_Node::SETTINGS_OPTIONS. var num_partitions = 1: the fleet runs once whatever the data partition count.

The fleet name scopes every cursor

<topology> rides every offsetlog and dead-letter path, so a request-builder fleet and a job-router fleet tailing the same firehose.pN keep separate cursors. Composing them collapses that byte-identical Consumer line into one reader.

Five <eln:> tokens

is_hub, stats_mirror_node, stats_mirror_lifetime (derived: twice stats_retention_seconds()), stats_mirror_segment_size and stats_mirror_num_segments (0 follows the substrate value in force). <config:…>, <partition> and <topology> are the substrate's.

Shell names, not class names

make_node Request_Builder resolves to \Newspack_Event_Logger_Nodes\Request_Builder_Node by scanning the registered namespace prefixes; Consumer, Partition, Tee, Topic, Age_Sieve and Remote_Source resolve under the substrate's.
