Six bundles, two transports, and no data that did not come through a node

Every tree separates the chrome from the data the same way: the root renders, one hook declares the node graph behind it, and rows reach React off a view node. Three dashboards stream a partition glob; three ask a service CI by command; the six page globals carry what the server knew before the first command ran.

By command: POST /wp-json/newspack-nodes/v1/command

A TM_COMMAND minted FROM the dashboard's own Request node, answered TO = FROM, so the reply lands on the node that asked and no correlator exists. A batched Fetcher sends one POST per tick; useCommandOnce parks a one-shot in the same outbox. Reads retry a MISSING reply and supersede; writes do neither. The server owns the set: search, sort and page are reported upward, never applied in the browser.

By stream: GET /wp-json/newspack-nodes/v1/messages/stream?subscribe=<glob>

A RemoteLink owning one SseIn child, the shared _heartbeat keeping its slot, a pass-through Tee, and one view node shaping each 7-field envelope into a row. The log tables read rows off the view node each frame, and Inflight samples the view's snapshot into state on the operator's cadence, so a busy stream re-renders at that cadence, not per message.
