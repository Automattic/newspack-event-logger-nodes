Every stat is a Ledger row: the scope in the key, the member beside it, the columns the Ledger declares

Nine Ledgers hold the stats, each one SQLite file every flame-builder partition appends to (decisions 1 and 36). flame-builder.tsl declares them and Stats_Store::LEDGER_COLUMNS spells each declaration once in PHP. A read names its window and its keys, and the Ledger aggregates the rows it finds.

One row, component by component
t
the start of the five-minute bucket the request finished in
,
k
the scope: the site, a server, a dimension, a URL
,
x
the member the scope holds: a value, a category, a URL
,
w
the partition that wrote the row
,
s
a sequence of the writer's, one per row
,
c0 … cN
the columns the Ledger declares, in order
A settle appends [ t, k, x, columns ]; the Ledger adds w and s and stores the row under PRIMARY KEY ( t, k, x, w, s ). A second row for one ( t, k, x ) is another settle's delta, and every read sums them.

server_key()

The FNV-1a hash of the server name, so a Host header puts no bytes of its own into a key. stats:names turns it back into a name.

url_key()

The URL with its whitespace percent-encoded, since a key holds none, and nothing else changed.

The flame blob is not a row

The flame-stats:url Table, one per partition, holds each URL's flame and profile under its hash, capped to ITEM_BUDGET, 900,000 bytes, by its producer.
