A duration nobody measured is not a timing sample

Flame_Builder_Node::accumulate_all_stats() runs two independent gates on every completed request. Read across a row to see what an evicted or aborted request still adds, and what it never touches.

Gate 1 · $count_global (decision 15)

! is_worker

Keeps worker traffic out of every site-wide aggregate, because one long-running job would otherwise dominate the averages. The per-URL row keeps worker timing on rows of its own.

Gate 2 · $record_timing

duration_ms > 0 && error_status ∉ { T, A }

T: Request_Builder_Node::evict_request() stamps it, with now − start, on a trace the LRU evicted mid-request. A: Log_Manager stamps it when a cooperative stop lands inside finish(), or when end_job_context() is told the job never finished. Both durations measure time to an interruption, not what the request cost.

So count and timed_count diverge

For a reason that has nothing to do with workers: the row records worker traffic separately, in ROW_WORKER. Performance_CI_Node::mean_ms() divides sum_ms by timed_count, while avg_peak_mb divides by count.
