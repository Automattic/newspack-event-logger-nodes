What the hub sends out, and what it does with what comes in

Both control minters run on a 300 second tick and fan out by hand, one signed command per spoke. Inbound, one node relabels every job entry before it reaches the hub's own firehose.

Why every 300 seconds, and not only on change

The tick re-pushes every registered option, so a spoke that is offline or newly connected converges without anyone touching the option again.

Why a Tee cannot do the fan-out

A signature verifies only at the spoke it is minted for. Re-addressing a signed command after the mint makes it verify nowhere, so each minter signs once per spoke.

The ruleset arrives whole.

The rules push inlines every pointer rule's hooks, so a spoke never receives a rule pointing at a table it does not hold.
