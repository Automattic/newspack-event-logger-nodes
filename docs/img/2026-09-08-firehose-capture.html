What the logger writes, and the three ways it leaves the site

Two programs write the firehose and redact the same way. The hub copies the lines raw. The Ask brief leaves by a different door.

On the spoke: two writers, one redaction

Log_Manager::message() · Gyrobase::Log::_write_entry

URL query string — a denylist of 25 parameter names. A parity check holds both writers to the same list, applied in the same place.

Hook arguments — every key kept, every value replaced by ? unless its key is one of 104 allowed names.

SQL — every quoted literal becomes ?.

One entry per request, environment_v3, is a map of 34 server variables: REMOTE_ADDR, HTTP_USER_AGENT, HTTP_X_FORWARDED_FOR, the JA3 and JA4 fingerprints.

Each entry is capped at 3,840 bytes so the append stays atomic.

2 · read by an operator

The request-detail and request-grep commands need the read capability. The account the hub logs in with holds read and tune, the smallest role the plugin defines.

3 · the Ask brief

A summary of one request, one URL or one entry, shaped for pasting into an AI assistant. Its env field keeps six keys. Its entries field copies up to 60 entries verbatim, environment_v3 among them.

Dashboard — shows the entries as a count only.
MCP tool performance_ask — returns the whole brief to an AI agent holding a read session.
"Ask Claude" link — an entry brief renders its message in full and carries it to claude.ai in the URL.
