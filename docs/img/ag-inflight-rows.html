Each running request reaches the log as its own row every second, and the browser tells rows from completions by state alone

On the left, Request_Flight_Node reads Request_Builder_Node's in-flight map on the Router's 1 s TIMER, fits each row to the 4096-byte line cap, and the completion summary joins the same partition. In the middle, gyroscope.p0 interleaves the two record shapes. On the right, GyroscopeView folds them and snapshot() reaps, sorts and caps what the table renders.

Request_Flight_Node · hidden Timer_Node sibling

fire() rides the Router's TIMER, every 1 s

set_inflight_target gyroscope:partition arms it: a non-empty string target registers the hitchhike, and any other value stops the timer. inflight_snapshot() builds one row per rid, with eleven keys:

methodurlstatewhattime_msest_msstart_timelast_log_tslag_msremote_addruser_agent

state is the innermost open span's name, or process when none is open. est_ms is time_ms plus the age of tracker_ts, so an idle row's estimate keeps growing.

which rows go
Full mode (default)

Every row, every tick. A fresh subscriber holds the whole cache after one tick.

Delta mode

Only rows whose last_log_ts is not older than the fire watermark.

per row

One TM_STRUCT per row, fitted to 4096 bytes

Line_Fitter::fit( $message, [ 'url', 'user_agent' ] )

It measures the packed line plus its newline. It halves url until the line fits or url is empty, and only then starts on user_agent.

url ÷2 … ''→user_agent ÷2 … ''→still over: null

A null is dropped with print_less_often(): at most one dropping oversize in-flight row warning per 60 s for the node, naming the first rid.

The watermark governs a dropped row's retry

last_fire_ts takes the fire's start time, and only when at least one row shipped. Full mode never reads it, so a dropped row is offered again every tick. Under delta mode, once any sibling ships, the dropped row's last_log_ts falls behind the watermark, and the row is not offered again until its request logs a new line. The browser keeps the last row it received for that rid, unrefreshed.

Request_Builder_Node · on completion

A finished request becomes a ten-key summary

On process (complete), or when the LRU's timed rotation evicts a stalled request with error_status T, emit_request() writes the full document to requests.pN and the summary to completed:tee, which copies it to completed.p0 and gyroscope.p0.

Its state is always complete, and it gets the same fit and the same rate-limited drop. The rid then leaves the map, so no later tick offers it.

GyroscopeViewNode · fill()

The fold reads KEY and state, and nothing else

state = complete

_complete() merges over whatever the rid holds and sets time_ms and est_ms to duration_ms. A completion for a rid never seen in flight is still recorded.

any other state

_inflight() upserts and stamps _seen, unless the rid is held as complete: then the row is DROPPED, having lost the race with the completion. The guard lasts until snapshot() reaps that completion.

A string or array VALUE, an empty KEY or a missing state is dropped. With no mode flag, one fold is correct under full and delta mode alike.

Inflight · the refresh tick

React samples the model on the operator's cadence

100 ms to 10 s, 2 s by default, set by the dropdown or the 0–9 keys. Each tick calls snapshot( maxRows ) (GyroscopePage passes 100), then reads .rps. No streamed message re-renders React.

the only caller, and the only reaper

The table reads slowest first, and slice( 0, maxRows ) can cap a short request out of a busy tick. A completion capped out is deleted all the same, and never renders.

GyroscopeViewNode · _updateRequestsPerSecond()

rps: the reaped completions over a 10 s window

Each snapshot files its completions under the current second; a bucket 10 s old leaves the running total, and rps = total ÷ 10. A silent stream decays to 0 over about 10 s. The clock is the snapshot's, not the completion's.

Three ways a row leaves the table

A completion arrives, normal or timed out (T), and the next snapshot shows it once and deletes it. Fifteen minutes pass unrefreshed, and the snapshot deletes it unrendered; that and a reconnect are the only exits for a request purge discarded, which emits no summary, or for a producer that died. The stream reconnects, and its clear empties the model.

Delta mode stops refreshing an idle row

A row whose request logs nothing is not re-sent, so its _seen stops advancing: a request silent for 15 minutes leaves the table while it is still running. Full mode refreshes every row each tick, so only a row the server stopped offering ages out.
