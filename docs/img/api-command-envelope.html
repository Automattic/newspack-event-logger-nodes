A /command body is one packed Message per line, and the HTTP status is decided once

Build a request by hand from the slot row, read the gates it must pass in order, and read the status it comes back with. The reply is a Message too, sent TO the FROM the request carried.

One line of the body: a 7-element positional JSON array, Content-Type: text/plain
0TYPE8TM_COMMAND
1TIMESTAMP1756900000
2FROM""the sender's node; the door prepends _output. Empty: the reply lands in the body.
3TO"performance"the CI: performance, discovery or rules. Most callers name the CI alone; a sub-path names a child.
4ID""
5KEY""
6VALUE{ name, arguments, auth }the verb, its tokens, and the signature

arguments: one flat token array

The grammar Command_Args::parse() and the browser's parseCommandArgs() both read. Required values ride positionally, in the order the verb declares; optional ones are --key=value; a boolean is a bare --key (--key=false turns one off); a list is comma-separated inside one value.

["--limit=25", "--server=example.com"]

auth: the envelope Command_Auth::sign() stamps

A nonce and a sig over [ts, name, arguments, nonce], plus a handle when the key is a session key.

An in-process (LOCAL) command needs none; anything arriving over the wire is refused without one.

Why text/plain

JSONL is not one JSON document. Sent as application/json, WordPress parses the body itself and answers rest_invalid_json before HTTP_In_Node is reached.

The gates, in order

HTTP_In_Node::check_permission()

403Bootstrap::fleet_gate(): the fleet is network-global, so a multisite subsite is refused.
401 / 403Not Capabilities::READ, the substrate's lowest role: rest_forbidden, 401 for a visitor and 403 for a signed-in user. The door demands the least any verb behind it needs.
429Over RATE_LIMIT_BURST (30) POSTs per user per RATE_LIMIT_WINDOW_S (1): one transient per clock-second. The newspack_nodes/command_rate_limit filter tunes it, clamped to at least 1. Counted after the capability, so an unauthenticated flood cannot poison the transient table.

HTTP_In_Node::dispatch()

500The request-scope graph is missing _router or _output: answered before any command runs.

Service_CI_Node, per handler

per verbService_CI_Node wraps each handler in Capabilities::require() for the role its schema declares; a verb declaring none takes MANAGE. No handler in this plugin re-checks.

The status, decided once

Did a reply reach the body? The first one written opens it, and the status line is spent.
200a reply is on the wire
401a command earlier in the batch had already been refused
Nothing written back once the batch has run?
202the work routed onward; its replies are due on the caller's own SSE stream
401any command in the batch was refused

The reply Message

TM_COMMAND|TM_RESPONSE, sent TO=FROM, whose VALUE is { name, arguments, payload }: the verb it answers, the tokens it was given, and the verb's return under payload.

A verb that throws answers TM_COMMAND|TM_ERROR instead, whose payload is the throw's message. No promise registry, no rejected Promise: the refusal lands a tick later on the node that asked.
