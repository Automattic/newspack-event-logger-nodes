The live hub is five lines, and 241 names

The top-level topology names two includes. Each include carries one leg per spoke, generated rather than hand-written, and each leg is what one spoke costs the hub.

aggregator-hub.tsl · the whole top-level file
var on_demand_idle = 0
The worker never idles out, so the streams stay open.
var num_partitions = 1
One instance holds every spoke.

secure

aggregator-fdn.tsl · one leg per spoke
make_node Remote_Source firehose:bend bend firehose.p<partition> <config:offsets_dir>/<topology>.firehose.bend.p<partition> <config:deadletter_dir>/<topology>.firehose.bend.p<partition>
Four arguments: the Vault id, the spoke's partition, an offsetlog directory and a dead-letter directory. It reads like the consumer it is, one whose log lives on another site. Scoping the cursor by topology name keeps two hubs off one offsetlog.
command_node firehose:bend:config assume_clean_shutdown true
Beside it on every source. Each record is durable in the hub's log before the worker stops, so a cooperative stop commits past the in-flight record instead of replaying it. Without the line, every worker recycle delivers one record twice.
command_node firehose:bend:config set_multi_writer true
On every firehose source. Every request process on the spoke appends to the log, so a request can still be writing a segment after the next opens. The verb asks the spoke's reader to hold the old segment for a grace period.
connect_node firehose:bend remote-job-rewrite
Every source sinks into the one rewrite node, and from there into the hub's own firehose Topic.
× 24 spokes, then secure.
hub-control-fdn.tsl · six more lines per spoke
make_node HTTP_Out settings:bend bend
The outbound leg, reading the same Vault entry the source reads.
command_node settings:bend:config allow_replies_to settings-sync
command_node settings:bend:config allow_replies_to discovery-collector
The reply gate, twice per spoke: 48 declarations. The list fails closed, so an omitted line drops that spoke's acks silently.
connect_node settings-sync settings:bend
connect_node discovery-collector settings:bend
Both minters fan out by hand. A Tee cannot do it: re-addressing a signed command after the mint makes it verify nowhere.
connect_node settings:bend null
One shared Null catches whatever the spoke leaves unaddressed.
× 24 spokes, then secure.

What firehose:bend costs: seven names

The operator writes the one Remote_Source line. The node builds the rest itself on its first tick, and each takes a name in the worker's registry.

firehose:bend · the source
├─ firehose:bend:config · verbs
├─ firehose:bend:sse-in · the stream
├─ firehose:bend:http-out · commands
├─ firehose:bend:null · unaddressed
├─ firehose:bend:firehose.p0:offsetlog
└─ firehose:bend:firehose.p0:deadletter

The three in blue are hidden: the source owns them, names them after itself, and rebuilds them when its credentials change.
