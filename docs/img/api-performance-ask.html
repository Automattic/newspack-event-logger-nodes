Three things a reader asks the performance CI for, and what bounds each answer

The URL modal's request list reaches back to a floor that is a function of min_lifetime; a picker descriptor decides which board a brief answers from; and a findings record says where each number was measured and what rule edit would act on it.

dump_url: requests reaches back to requests_window_start, and no further

The floor is Stats_Store::window_start(): min_lifetime, floored at PREFIX_FLOOR (3,600 s), rounded up to a whole five-minute bucket, and capped at the MAX_READ_BUCKETS (288) a reader enumerates. A request that completed before it is absent by design, not by truncation. since is compared against COMPLETION (timestamp + duration_ms), not start, so requests is the tail while requests_window_start still names the floor; the dashboard's merge accumulates.

between⌈min_lifetime ÷ 300⌉ + 1 buckets: the floor tracks the setting.
min_lifetime > 85,800 s288 buckets: the floor stops 86,100 s back.

One findings record; the list comes back worst first

severityhigh · medium · info, and that is the sort.
kindfatal · insufficient_instrumentation · unattributed · dominant_span · repetition · entry_gap · truncation
title, detailThe prose.
metricA numbers object whose keys follow the kind.
rule_idThe rule admitting the request, or null when none does.
measuredWhere the number came from: flame · profiles · subtraction · entry timestamps · record markers · php fatal · rule + record · url stats. A share read off the flame tree and one obtained by subtraction warrant different confidence.
proposalThe rule edit that would act on the finding. Every kind but fatal carries one: no rule edit fixes a crash.
actionadd_hooks · trim_hooks · mark_significant · add_custom_events · create_rule · none
directionmore · less · none. As often more as less: a proposal that only ever turned monitoring off would make the system blinder each time it was taken.
why, undoThe reason, and how to take it back.
pattern, hooks, field, valueWhichever the action needs.

Where the list appears

dump_request computes it, and the request: and url: briefs carry it, so the picker and an agent read identical evidence.

Every brief carries the caveat

The logger times only what a rule names. Unattributed time is unmeasured, not idle, and a brief without that sentence invites an invented cause.
