Rule_Matcher sorts the ruleset once, by rank and then by pattern length within a rank, and stops at the first hit. Matching is case-insensitive, by raw string prefix rather than path segment, and cached per normalized path?query, misses included. No match means skip.

Length breaks ties WITHIN a rank only

This is not longest-prefix-wins: a one-character exact pattern outranks the longest prefix. A rule's id is url_hash( pattern ), and every write path that accepts outside rules re-derives it, so a supplied id is ignored and there is one rule per URL.

The rule list: one autoloaded option

newspack_event_logger_nodes_rules

Every rule, with its hooks inline while they number at most INLINE_HOOK_LIMIT = 100. The common small-rule path pays no cache hop. rekey_by_pattern() re-derives every id and collapses duplicate patterns, last entry winning, on every write path that accepts outside rules.

A heavy rule's hooks: a non-autoloaded option, the system of record

newspack_event_logger_nodes_rule_hooks_<id>

Past 100 hooks the list moves here, so a heavy rule does not bloat autoload, and the rule stores hooks = null, hooks_in = mc. save() applies the threshold, writes the option, warms the mirror, reconciles orphans and re-tiers so rules() == load().

Its warm mirror: the substrate's Table

Table_Node::table( TABLE_HOOKS, TABLE_TTL )

'eln-rule-hooks' at 3600 s, keys scoped per install. The accessor is nullable: a host with no cache backend has no warm mirror and reads the option. wp nodes ruleset-bench measures both tiers; 65 is the limit's floor.

Over the wire, hook-complete

Rule_Set::hydrate_array()

Inlines each pointer rule's resolved hooks for a settings-sync push; apply_synced() re-tiers on the spoke and writes heavy hooks back out to the spoke's own option. A read skips an unrepresentable rule with a rate-limited notice; a write lets the throw stand and keeps the last-good ruleset.
