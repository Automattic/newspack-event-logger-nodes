A flame tree is a stack machine over spans, merged by name and averaged per request

Flame_Tree is stateless: four static stages Flame_Builder_Node runs in order on each record it reads from requests.pN; a record carrying Request_Builder's pre-folded flame skips the first. The per-request tree goes to flames.pN; the merged one is the URL's aggregate flame.

1build_flame_data()

One request's entries, in order. The root is request, t = 0.

init hook (start) ts +12 ms
  http (start) l=Plugin::fetch m=api.example.com
  http (complete) duration_ms 212
  http (start) l=Plugin::fetch
  http (complete) duration_ms 30
init hook (complete) duration_ms 340
template (start) never closed
wp_head hook (complete) matches nothing: dropped
  • A start pushes a node named <base>: <l>, with detail from m when it differs, and t, the offset in ms from the request's own start. t is absent, never zero, when unknown.
  • A complete matches the nearest open node of the same base name, LIFO, stamps value = duration_ms, and pops it with everything above it. Children that outlive their parent keep value 0.
  • The stack, root included, holds MAX_STACK_DEPTH 50, so 49 spans nest; a deeper span is attached but never pushed.
  • Then duplicate siblings get a hidden \x00N suffix, so the merge cannot collapse them, and cover_children() raises every parent to the larger of its children's extent and their sum.

2The per-request tree

strip_name_suffixes() removes the \x00N numbering before the tree is stored or shown. The caller takes the greater of the covered root and the request's measured duration_ms.

A flame value is a LAYOUT width: cover_children() raises a parent over its children, so every stat reads duration_ms instead.

3merge_flame_children_incremental()

Into the URL's aggregate, keyed on name, recursively:

new name → { name, sum_value: value, ts: now, children: [] }
seen name → sum_value += value; ts = now
children → the same merge, one level down
ts < now − 3600 → dropped

An incoming node's detail and t never reach the aggregate, which has merged many requests and holds no single position. No per-node tally is kept.

4finalize_flame_node()

value = sum_value / requests the aggregate covers

The divisor is the aggregate's own request count, never a per-node tally, so a node seen in a minority of requests averages down: the flame shows mean cost per request. The blob, url:{hash}, carries no bucket, and a reader takes the first partition's blob whole rather than summing across partitions.

The resumable twin, Flame_Fold

The same stack machine, static over a plain-array state so it can ride the Consumer's checkpoint frame, and MERGING as it goes: same-name siblings under a parent collapse into one node with count, summed value, max and a merged flag, so a folded envelope costs O(distinct paths). Its stack starts empty and holds MAX_STACK_DEPTH 50 spans.

Exclusive time lives elsewhere

The assembled record's profiles map, built by Request_Builder_Node, credits a span's duration to its own category and subtracts it from every open ancestor up to the first non-callback one, so a hook's number is its own work. The leaderboards, dump_url and RequestProfile read that, not the flame.

In the browser

pruneFlameGraph() keeps every frame at or under 1,000, then frames ranked within that or worth 0.001 of the root, and raises the cutoff past 5,000; withTimeSpacers() turns t into a real x position by inserting transparent spacer frames, declining any family with a missing t, a merged node or overlapping children.
