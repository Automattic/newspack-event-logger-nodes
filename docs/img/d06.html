What one request writes

Four gates decide whether the request is logged and what is timed. Past them, Log_Manager appends one line per event to the firehose, an append-only topic; the request id is the message key, so every line of one request lands in one partition, firehose.pN.

1

Master switch

With enable_logging off, nothing is written. The other two switches are log_memory and flush_every_line.

2

Not root

The writer refuses to run as root.

3

The rule

A rule pairs a URL pattern with a verdict, log or skip. Specificity outranks list order; length breaks ties only within a rank.

No match means skip. The seed ruleset is one log rule on the path /, beside five exact skips: cron and the runtime's own endpoints.

A rule's id is the hash of its pattern, so one URL never carries two rules.

4

What the log rule binds

The hooks to time, the custom events to log, and the events to profile per callback.

Outbound HTTP: timed by default, one span per remote call; a rule can turn it off.

SQL: timed only when a rule asks. The closing hook fires only under SAVEQUERIES, and each query costs two entries.

Nothing bound: the Performance dashboard's findings report insufficient instrumentation rather than guess.

Over the cap

The entry is marked truncated and the payload is trimmed ten percent at a time until it fits. The category is never trimmed: a shortened start never pairs with its close.

Anything that can exceed it goes through the runtime's job intake

The intake takes a write lock and accepts a payload of up to 32 MiB.
