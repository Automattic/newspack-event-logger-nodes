Every stats key takes its bucket or hour right after the namespace, and the URL index is stored at two resolutions

Stats_Store asks three SQLite Tables through the substrate's Table, which stores no install scope; below that, one partition's keyspace is evlog:p{N}, then the namespace, then the bucket or hour, then the scope parts (Stats_Store::key_at()), so everything one flush touches in a namespace sits together in key order, one MGET per Table serves any mix, and retention is the row's own TTL.

evlogthe stats keyspace
p{N}the flame-builder partition
{namespace}one of nineteen
{bucket}Y-m-d-H-i floored to 5 minutes for the URL index's fine tier, or Y-m-d-H for an hour key
{scope parts}a list set, a server's fnv1a32, a shard, a url_hash, a dimension

Within a namespace, lexical order is chronological order, so one flush's current-hour keys are one run of the Table's index. A chart hour key holds its twelve five-minute slots, and a leaderboard hour one sum (decision 35). Three namespaces carry no time: url and urlmap key on a hash, urltoken on a server and a word.

What one read of the URL index asks for

The fine tier lives 7,200 s: the current hour, and the hour just closed, which folds at its first flush and takes late writes for a while after. At that width it costs 24 buckets a shard, against the 25 hours the coarse tier stores at the default window. Performance_CI_Node::load_index_default() folds INDEX_READ_CHUNK 12 buckets at a time and drops each chunk before reading the next.

Indexes 0 to 8 ADD, in ROW_SUMS order, 8 the requests that timed out or fataled; extremes at 9 and 10 stay the URL's own. Index 14 is the row's one string, its path: no scheme or host for an https URL under the key's own server, the whole URL otherwise, cut to MAX_PATH_BYTES 1,024. The host lives in the key, so a scope is the server's own keys and every read walks the shards urlsrv names. Measured on live rows: 672 bytes named, 398 positional.

Caps fold into a synthetic Other rather than dropping, so a total summed from a capped namespace stays exact. Every value but a slotted chart hour is capped BEFORE it is written to ITEM_BUDGET, 900,000 bytes uncompressed, by an estimate for the configured serializer: fixed bytes a part plus the strings it carries. The one cap that does not fold is a payload bound: sums_to_display() keeps a category's fifty slowest entries by average exclusive time past a hundred.
