Three producers, four logs, one router, and a sieve that counts from enqueue

Which producer a job takes is decided by two questions: does the payload fit in PIPE_BUF, and must the job reach a hub. Whichever log it lands in, Job_Router_Node normalizes it onto jobs.pN, the Age_Sieve drops it past 900 seconds, and the substrate's Job_Worker runs it.

producers, inside a request
Log_Manager->message( 'job', payload )

Under 4 KB, PIPE_BUF atomic. The ONLY path a hub aggregates: firehose entries alone cross a spoke's SSE pull. An oversized one arrives at the router with m stripped and reads as an invalid handler.

Job_Intake::feed( handler, id, parameters )

Under PIPE_BUF, no lock, local only. Lets the site run job-feed, whose reader tails jobs alone rather than every line of every request.

Job_Intake::queue( handler, id, parameters )

Up to MAX_JOB_SIZE 32 MiB, behind the partition's write lock, local only. Serialized option blobs, image-handler args, large arrays go here.

Job_Router_Node

A nested array under m is the body; otherwise the entry is. Out: { k, handler, parameters, ts } + id + the DISPATCH_FIELDS it carries: retries, attempt, batch, key. Kind from the ENTRY's k. No size gate, no age gate, no arguments.

Age_Sieve 900 1

Drops an envelope whose TIMESTAMP is older than 900 s, warning on. Message::unpacked() restores the TIMESTAMP the producer stamped and forwarding never rewrites it, so age counts from ENQUEUE: when the fleet stops draining, every job enqueued more than fifteen minutes before the router catches up is discarded as it is read, cursor advanced, nothing dead-lettered. Raise max_age where jobs are not disposable.

handlers by kind

job → newspack_nodes/job_handlers; remote_job → newspack_nodes/remote_job_handlers; the worker drops an unregistered name silently, after the read

Three partition-selection modes

pinned: $intake->partition( $i ). keyed: Partition_Node::hash_to_partition( $key, $num_partitions ), identical to the firehose. round-robin: a static counter modulo PHP_INT_MAX, for callers with no meaningful key. A future not_before is applied after the mode runs, so it still advances the round-robin counter, then parks the job in jobdelay.p0.

write_job() options

retries and attempt for Job_Worker backoff, batch for batch settlement, unique + unique_ttl for enqueue dedup within a window (needs a cache backend), delay / not_before for scheduling. An unknown option key throws, so a typo stays loud.

The lock is per partition

Partition_Node::allow_large_writes() takes the partition's write lock on the call and holds it for the partition's lifetime; it waits DEFAULT_LOCK_WAIT_MS 15 s and throws when a live writer still holds it, which queue() reports as false. queue() releases it in a finally, the destructor covers an instance that never closes, and a batch caller reuses one instance across queue_many() so the acquisition cost amortizes.

Two rejections warn, three do not

An invalid handler name (HANDLER_NAME_PATTERN /^[a-zA-Z][a-zA-Z0-9_-]{0,63}$/D, whose D refuses a trailing newline) and non-array parameters are malformed jobs: rate-limited warnings. Wrong type flags, a non-array VALUE and a kind other than job / remote_job are ordinary firehose traffic and return silently.
