A stored URL row is positional, and its indexes are named constants

serialize() writes every key NAME into every entry, so a named row spends s:11:"timed_count";, 19 bytes, to say what i:1; says in 4, once per row per field, on a read that fans out to thousands of keys. The URL index earns the shape on memcache; the category and dimensional series earn it on the mirror, which keeps a whole window of frames. $row[3] is forbidden: the constants buy back the readability the shape spends.

Where an index becomes a name

ROW_FIELD_NAMES is the one map, beside the constants it names, in the shape Message::TYPE_NAMES sets, because a private copy is how a reader ends up omitting a field. Performance_CI_Node::fold_index_row() is the one storage/display boundary for the ROW: everything above it is positional, the display row keeps its names because it crosses the wire as JSON, and a second copy of the translation is how the table and the modal come to disagree about one URL.

The PATH crosses as url: fold_index_row() puts it on the display row, and resolve_urls() replaces it with the whole URL urlmap joins for the rows a page shows. A thing crosses a boundary where it is CONSUMED, not where it is convenient to convert.

CAT_SUMS has no CAT_FIELD_NAMES, and that is not an omission: compact_category_series() emits a POSITIONAL wire row, so no index ever becomes a name, and a name table with no naming site is a second shape waiting to drift. DIM_SUMS has none for the same reason — it stays positional to the wire, where two React sites index it.

The path is display, and the host is the key's

Stats_Store::row_path() keeps the path and query with no scheme or host when the URL is https under the row's own server, whose name the key implies (decision 30), and the whole URL otherwise, so an http row never displays as https.

https://kea.test/wombat-7731under kea.test's key: /wombat-7731
http://kea.test/wombat-7731kept whole: the scheme is not the key's to imply

The hash is the row's identity and the path its display. A merge keeps whichever side's path is non-empty, and an overflow row's is empty, because one path describes none of the URLs it folds. The byte cap counts every row's path. The suite pins the shape in ONE test that reads a shard raw and translates everywhere else.
