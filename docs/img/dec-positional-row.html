A stored URL row is positional, and its indexes are named constants

serialize() writes every key NAME into every entry, so a named row spends s:11:"timed_count";, 19 bytes, to say what i:1; says in 4, once per row per field, on a read that fans out to thousands of keys. The URL index is the one value dense enough to earn the shape. $row[3] is forbidden: the constants buy back the readability the shape spends.

Where an index becomes a name

ROW_FIELD_NAMES is the one map, beside the constants it names, in the shape Message::TYPE_NAMES sets, because a private copy is how a reader ends up omitting a field. Performance_CI_Node::fold_index_row() is the one storage/display boundary for the ROW: everything above it is positional, the display row keeps its names because it crosses the wire as JSON, and a second copy of the translation is how the table and the modal come to disagree about one URL.

The SPLIT never crosses: swap_url_server_sums() merges one server's sums into the row and unsets it, project_row() unsets srv_recent, and every escape from the index goes through that projection. A thing crosses a boundary where it is CONSUMED, not where it is convenient to convert.

CAT_SUMS has no CAT_FIELD_NAMES, and that is not an omission: compact_category_series() emits a POSITIONAL wire row, so no index ever becomes a name, and a name table with no naming site is a second shape waiting to drift.

A split of one server is the row restated

A stored url is ABSOLUTE, so on a fleet of disjoint sites every URL has exactly one host: this is the COMMON row. COUNT alone decides it, because every URL_SRV_SUMS field is summed into the row and the split from the same increment.

"host" => nullthis host's numbers ARE the row's
host absentnever served here: the row drops from a scoped read

collapse_sole_server() and expand_sole_server() are the pair, and every merge, reader or writer, expands BEFORE summing: merge_url_row() and fold_url_rows() do it for both sides, which covers the re-flush, the coarse fold and the overflow tail. sum_fields() skips a non-array value, so an unexpanded null is not a zero but that host deleted from the merge. The rule names writers too, because a write-side merge that skips the expansion breaks no reader's test. The suite pins the shape in ONE test that reads a shard raw and translates everywhere else.
