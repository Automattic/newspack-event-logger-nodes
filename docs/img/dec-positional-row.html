A Ledger's columns are positional, and their indexes are named constants

An APPEND row carries its columns as a list in the order the make_node line declares, and a SUM or TOP answers them in that order. So a reader names a column by constant, never by index: $row[3] is forbidden, and the constants buy back the readability the shape spends.

Where an index becomes a name

ROW_FIELD_NAMES is the one map, beside the constants it names, in the shape Message::TYPE_NAMES sets, and it spells each column as LEDGER_COLUMNS does, so the topology and the reader cannot drift. Stats_Store::url_row() is the one boundary where a URL row's positions become the names the wire carries.

The series stay positional to the wire

compact_dim_series() sends [ nameIndex, count, sumMs, sumPeakMb, timed ] and compact_category_series() [ nameIndex, t, c, n ], under a name table spelling each name once, so neither needs a field-name table: no PHP index ever becomes a name, and the dashboard's one decoder, decodeNameTable(), names the fields.
