A stream costs a slot, and only the client keeps the slot alive

The three streaming dashboards and a hub's Remote_Source pull all consume the substrate's GET /wp-json/newspack-nodes/v1/messages/stream. Nothing here is this plugin's server code: SSE_Out_Node is the controller and the drain loop, and SSE_Slot_Pool is the rate limit, which is why losing the pool fails CLOSED where the stats path fails soft.

Browser

A RemoteLink node owning one <name>:sse-in EventSource child, and the page-wide _heartbeat and _http singletons every link shares.

SSE_Out_Node

The /messages/stream controller and its drain loop, one php-fpm child for the life of the stream.

SSE_Slot_Pool

Two cache keys per slot, an owner pointer and an expiring lease, in memcached when one is configured, else APCu.

1One or more partitions or globs: errors.*, gyroscope.*, completed.*, or a hub's firehose.pN. A machine pull sends X-Newspack-Nodes-Pull.
2Six slots a host (sse_max_streams), three per identity (sse_max_slots), for a browser and a pull alike; SSE_Slot_Pool::wire() passes reserved = 0 for a pull, which the SSE_In inside a Remote_Source announces with that header, so it may claim the trailing sse_reserved_slots a browser stops short of. A full share, a full host, or no store answers 429. acquire() reads through Cache_Backend::shared_first(), which takes the configured memcached handle and falls back to APCu only when none is configured, so a configured memcached that is DOWN fails every slot write and answers 429 on every host.
3Carries the slot id and the lease owner. ensureChildren() hands both from the SseIn to the Heartbeat that has to keep them alive.
4The drain loop writes and flushes each frame as it goes, sends a heartbeat event every interval whether or not data flows, and once per tick, before the framework sleeps, flush_if_needed() writes a FLUSH_SIZE comment every SSE parser discards. The hub's Remote_Source resumes from JSON positions over this same surface.
5Only the CLIENT refreshes a lease, and only an owner-matched heartbeat counts. In the browser the shared _heartbeat node POSTs every 15 s (POKE_INTERVAL_MS); a hub's Remote_Source heartbeats through its own HTTP_Out patron. Every lease takes sse_slot_ttl, 60 s by default, floored at three Remote_Link_Node::HEARTBEAT_INTERVALs, 45 s, because a client that loses its session stops heartbeating for the whole re-auth round trip.
6The server never refreshes on check. When the tab dies the lease expires on its own, and the next slot check drops the stream and frees the slot. Reintroducing a server-side refresh-on-check would keep a dead client's slot alive for as long as the drain loop ran.

Two failure postures, deliberately opposite

Stats: fail-SOFT. Stats_Store never throws when memcache is unreachable: a read answers null / [] / false, so a dashboard shows "no data". SSE: fail-CLOSED. A new stream answers 429 when the pool cannot grant a slot, a dead memcached included, because the pool IS the rate limit and dropping it would let one runaway client saturate the worker pool. Do not unify them.

What this plugin adds on top

useErrorLogGraph, useGyroscopeGraph and useRequestLogGraph each pass a prefix, a glob and a view class to the substrate's useStreamGraph, the first and last through useGlobStreamGraph. It mounts the RemoteLink, a pass-through Tee and the view node that shapes envelopes into rows; it also closes the stream while the tab is hidden or paused and reconnects from the last seen offset on refocus. A hub opening one Remote_Source per spoke partition takes a 429 on the fourth, however many slots stand free.
