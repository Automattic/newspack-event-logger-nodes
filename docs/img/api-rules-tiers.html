Five rules verbs, one writer, and a hook list stored in one of two tiers

Every verb routes through Rule_Set, so a raw update_option() can never bypass the tiering or the orphan sweep. A rule's id is its pattern's hash, so the ruleset can never hold two differently-configured rules for one URL.

READdumpno arguments{ rules: [...] }, every pointer rule's hooks resolved to the full list and hooks_in normalized to inline: the editor never sees the tier.
TUNEsaveraw JSON array as the first token{ saved: int }. Whole-list replace; one unrepresentable entry throws before anything is stored.
TUNEupsertraw JSON object as the first token{ rule: {...} }. Keyed by pattern; an edit carrying the old id and a new pattern rekeys and drops the old entry.
TUNEdeleteid, positional{ deleted: bool }. Drop the match and re-save.
TUNEresetno arguments{ reset: int }. DELETES the option so the file config seeds again; storing [] would pin "log nothing". Sweeps every pointer option too.

Rule_Set::save(), per rule

A skip rule is stored as it is. A log rule's hook list is counted (a pointer rule is rehydrated first) and tiered:

hooks ≤ INLINE_HOOK_LIMIT (100) → inline
hooks > 100 → pointer

Then reconcile_orphans() deletes every …_rule_hooks_* option whose id is not a live pointer, the list is written to the autoloaded newspack_event_logger_nodes_rules, and every live worker is asked to re-read its config.

Two size gates before decoding

save and upsert refuse a blob over MAX_JSON_BYTES (65,536) as payload too large, decode at MAX_JSON_DEPTH (12), and refuse anything that is not an array.

Inline tier: the list rides the rule
Stored: hooks: [ … ], hooks_in: "inline", inside the autoloaded rules option every request already unserializes.
Any prior durable option and Table entry for the id are deleted, so a rule that shrank back leaves no footprint.
Read: hooks_for() returns the list.
Pointer tier: the list lives beside the rule
Stored: hooks: null, hooks_in: "mc". The two must agree, or Rule's constructor throws.
System of record: the NON-autoloaded option newspack_event_logger_nodes_rule_hooks_<id>, so the autoload blob stays small.
Warm mirror: the substrate Table eln-rule-hooks, TTL TABLE_TTL 3,600 s, keyed per install, backed by the option on a miss. A host with no cache backend has no mirror and reads the option directly.
Read with both absent: hooks_for() returns [] and prints a rate-limited hooks missing for pointer rule notice. The rule then binds nothing.

Why the crossover is 100

wp nodes ruleset-bench measures the three costs the tier trades: the alloptions unserialize every request pays for inline storage, the inline bind loop, and a Table fetch plus the same loop. INLINE_HOOK_LIMIT is the largest hooks-per-rule whose inline read still beats the Table fetch while the autoload tax stays negligible, and never below 65.

What crosses to a spoke

The hub's settings sync ships each rule hook-complete: the newspack_nodes/settings_sync/value resolver hydrates a pointer rule's hooks before the push, and the spoke's Rule_Set::apply_synced() re-tiers locally, writing heavy lists back out to its own option and mirror. A push that changes nothing does nothing.

Identity

Rule_Set::id_for( pattern ) is Log_Manager::url_hash( pattern ), re-derived on every write. upsert reads a client-supplied id only to find the entry an edit is moving; what it stores always comes from the pattern.
