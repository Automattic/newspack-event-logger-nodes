The breakdown panel is always mounted, and says which kind of nothing it has

BreakdownControls is the chart and the Metric and Breakdown dropdowns that drive it, plus a Server select when the caller passes one (the Overview card does): one panel, because the values the chart reads are exactly the ones its own selects set. Two callers mount it unconditionally, and each reaches the "not yet" state by its own mechanism; the wire guarantees neither on its own.

The Overview card

Reads overview.breakdowns[ dimension ], a map the server keys by every dimension it was ASKED for.

An absent KEY is a dropdown switch the reply has not caught up with: undefined.

overview REFUSES a dimension outside DIMENSIONS rather than answering about the rest, so list drift arrives as an error, never a panel hung in pending.

The URL modal

The url_breakdown reply carries one dimension and no key to look it up by, so the switch itself runs setBreakdownData( null ).

subjectOf makes the subject the (URL, dimension) PAIR: a superseded dimension's reply matches no outstanding ask, fills nothing and retires nothing.

The dropdowns render in all four. They are the only way out of a dimension with no rows, a read still in flight or a refused reply, so any gate that can unmount them can trap an operator. There is no "None" breakdown: the totals are never the requested view, and the chart holds no undifferentiated source to fall back to.

What a gate does

A gate that falls back to overview.aggregate_time_series when the selected dimension has no values draws a flat series legended "Total" under a dropdown reading "User Agent". A gate on breakdownData unmounts, on an error, the only control that can recover from it, because useCommandOnce treats a refusal as an answer.

Why pending and empty stay apart

"No User Agent data" during a fetch is a lie that flickers, and the totals under either state answer a question nobody asked.
