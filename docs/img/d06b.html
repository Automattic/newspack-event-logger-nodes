Who reads which partition

The firehose interleaves every request's lines. Four topologies pull them apart: request-builder, job-router and flame-builder belong to the plugin, job-worker to the runtime. The complete topology runs all four in one worker, with a Tee splitting one firehose consumer between the builder and the router.

Request_Builder_Node

Keys an envelope per request id, folds each line in, checks the line numbers for gaps, and emits the record when the terminal arrives.

The consumer checkpoints the envelopes into its offsetlog, so a respawned worker resumes half-built requests. A request silent for 600 seconds is evicted as timed out.

topology flame-builder

Flame_Builder_Node

Takes one record at a time. Writes a flame tree, nested spans each as wide as its duration, then folds the request into every aggregate: request totals, the slowest categories, a URL index, and time series by category and by dimension (status, method, server, country, user agent).

Flushes at most once every five seconds.
